- **14-r1 K1:** every run probed the temporary-name filter and every one reported the
  opposite defect: a file the agent itself names `o<ino>-<gen>-<seq>` has every change
  hidden (real at the head; its own doc comment promised less). None tried a path *under*
  a temporary directory name. Run 1 named the mechanism as an unverified design question
  ("children under a temporary parent path ... `o300-…/f`"); graded partial, the judge
  passed it as a miss.
- **19-r1 K4:** only run 4 followed the documented order and saw that `--enable-quota`
  needs a running agent that cannot boot with the limit set and quotas off.
- **19-r1 K2:** runs 1 and 5 built a fake cgroup without `memory.events`; the others never
  ran the script.

## Read

Precision is perfect and the reviewer is strong on what the prompt's axes name: tenant
cost, limits bypass, docs against ADRs. Recall is weak where the key needs host semantics
(cgroupfs sizes, pipefail, btrfs send's rename order) the runs could only reach by building
fakes; the prompt says to run scripts against real host output but the sandbox has none.
The 14-r1 miss is one probe away, but a prompt line aimed at it would restate the held-out
key, so it is not a variant to write. Next: more cases (the first reviewed agent_cloud PRs),
and file the off-key bugs above.
