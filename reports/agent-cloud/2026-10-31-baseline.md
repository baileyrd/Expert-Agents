# agent-cloud, 2026-10-31, baseline

Prompt: `experts/agent-cloud/` at this repo's `7c00a3ee` (`prompt_sha`). Cases:
[14-r1](../../bench/cases/agent-cloud/14-r1/), [19-r1](../../bench/cases/agent-cloud/19-r1/).
Five runs per case under the suite's blind settings (author-reported; see Blindness and
network); every finding graded in [2026-10-31-baseline/](2026-10-31-baseline/).

Runner: Eval-Kit from `~/src/eval-kit` on baileyAi (`python3 -m evalkit run --yes --jobs 2`,
alongside the rusty-tokio bench), Claude Code `2.1.314` on the signed-in login (no API key),
reviewer model `claude-opus-5-5`, judge `claude-sonnet-5-5`. agent_cloud clone at `9368efb`
(`main`, all case SHAs present). TMPDIR and build dirs on the main disk.

**Field-found keys.** No agent_cloud PR had a review round, so both keys list defects found
live on BaileyServ after merge and fixed by later PRs (#16; #20 and #22). Every key is
`ungraded`, so severity agreement is not measured. Two cases is below the three-PR bar;
Nano chose to bench on them anyway (2026-10-31).

**Blindness and network (author-reported, not independently verified).** The suite opens
only the crates.io hosts and denies `$EXPERT_AGENTS`, `$TARGET` and `~/.claude` to the
reviewer. This commit archives the final reports and graded tables only: no run-store
records, resolved sandbox settings or tool traces (those stay in the Eval-Kit store on
baileyAi), and Eval-Kit was imported from a local checkout whose revision is not recorded
here. So that each run could not reach later commits or the fix PRs is what the suite
intends, not something these artifacts prove.

The reports disagree on the Rust checks. Eight of ten say they ran `scripts/ci-local.sh rust`
(fmt, clippy, `cargo test`; 4 `ac-gateway/tests/notify.rs` tests fail on EPERM for Unix
sockets in the sandbox) after moving `CARGO_HOME` and the target dir to `$TMPDIR`; 14-r1-4 and
19-r1-3 say github.com was denied, so they ran no clippy or workspace tests. The workspace
pins rusty_mill as a git dependency, so the eight builds either reused a git checkout already
in the read-only `~/.cargo` or reached github.com.

**Trace check (2026-11-01, read-only, on baileyAi): the eight builds were blind to
github.com.** `~/.cargo/git/db` already held the locked rusty_mill rev `84eeeb42`, fetched
at 11:13 CDT; the bench ran 14:58-15:26 CDT, and nothing under `~/.cargo/git` changed after
11:14. The builds copied that database into their `CARGO_HOME`. The only github.com request
on record (19-r1-3, 15:17:38) got `CONNECT 403` from the sandbox; no allowed github.com
request appears anywhere. Residual gap: traces keep no tool output, so two runs' denied
requests to `raw.githubusercontent.com` and a `btrfs-progs` clone rest on their own reports.

**The runs were not independent.** All ten shared one `TMPDIR`, so 14-r1-2 seeded a shared
`CARGO_HOME` that four other runs reused, runs could read each other's scratch files, and
CI logs overwrote each other. This is no github.com leak, but per-run `TMPDIR` is needed
in Eval-Kit before the next bench. The verification read the Eval-Kit store, `~/.cargo` and
sandbox logs on baileyAi; it is author-run, not independently reproduced.

  ran the script.

## Read

Precision is perfect and the reviewer is strong on what the prompt's axes name: tenant
cost, limits bypass, docs against ADRs. Recall is weak where the key needs host semantics
(cgroupfs sizes, pipefail, btrfs send's rename order) the runs could only reach by building
fakes; the prompt says to run scripts against real host output but the sandbox has none.
The 14-r1 miss is one probe away, but a prompt line aimed at it would restate the held-out
key, so it is not a variant to write. Next: more cases (the first reviewed agent_cloud PRs),
and file the off-key bugs above.
