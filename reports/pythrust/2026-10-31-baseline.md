## Real bugs beyond the keys

Each was confirmed by a probe at the case head (`pythrust check`, `run`, the native build
and CPython; probes kept outside this repo) and re-checked on PythRust `main` at `c374e9e`.
Still on main, filed:

- [PythRust#70](https://github.com/baileyrd/PythRust/issues/70) (P1, 47-r1, all 5 runs): A5
  misses one list passed twice from module code when a loose callee, not the module code,
  stored one inside the other.
- [PythRust#71](https://github.com/baileyrd/PythRust/issues/71) (P1, 48-r1 5/5 and 48-r2
  3/5): a change through `(a if c else b)` or `(b or a)` escapes D4.
- [PythRust#72](https://github.com/baileyrd/PythRust/issues/72) (P1, 48-r2 run 5; 48-r1
  run 1 in part): one list `+` anywhere sends the program to the conservative fallback and
  silently drops every D3/D4 diagnostic; the roadmap says no such gap remains.
- [PythRust#73](https://github.com/baileyrd/PythRust/issues/73) (P2, 48-r1, 48-r2, 65-r1):
  D4 calls sets and dicts "a list" and names a `for` loop where there is none; D3/D4 fix-its
  that fail or change the result when applied.

Also real and still on main, not filed (docs and tests): grammar.md D2 says only `mut`
triggers the A5 error while the A5 entry and the code also count `owned` (47-r1 runs 2, 4);
roadmap A6 marked done with the D4 holes above open (48-r1, 48-r2); the A5 fix-it not saying
which argument to copy (47-r1 run 4).

Fixed on main since the head (`fixed_since`, 14): among them a callee's change to a module
global unseen by D4, a global and an element of another global assumed distinct, an
untested native refusal of an exception holding a list, `1 in {True}` refused natively, and a
stale `own::calls` comment.

No finding is a memory-safety bug in native code or `pythrust-rt`. Every real finding is a
static check accepting a program it should reject, a wrong diagnostic, or a native result
that differs from `run` and CPython: 65-r1's keyed K2 (`d.get("a", fill())` prints `0`
natively, `7` under `run`) and K3 (a missing bool key prints `caught 1`, not `caught True`).
Outside those two keys, the probes the graders and I built for non-key findings showed no
native/`run` difference; that is our verification, not a claim of general parity.

## Grading

Graded blind against the clone at each case head by four grader agents, one per case, each
told to probe every non-key finding rather than trust the report; I re-ran the probes behind
#70–#73 at the head and on `main` myself before filing. Findings are items under a report's
"Blocking findings"; design questions and optional improvements are not graded.

- **Design questions (3):** 48-r2 runs 2 and 4 attribute the whole-program fallback to the
  `x = print(7)` shadowing gap, which roadmap A3 documents as a kept fixture; 65-r1 run 3
  flags the bool-key store gap, which `native.md` lists as a known backend gap.
- **Judgement calls:** 48-r1 run 1 F1 as K2 `partial`; 47-r1 run 2 F2 (tempered wrapper
  and a global) triaged `fixed_since`, not a second K1 match; 48-r1's nested-list D3 fix-it
  graded real because the suggested fix fails, though grammar.md documents the rejection.

  other host and none hit a sandbox network denial.

  65-r1-3 and 65-r1-5 lost base-commit test runs or probes to it. Those runs traced their
  findings by reading source, so their recall may understate a run with room to build.
- **Each run** started from its own checkout of the case head fetched by SHA, with no later
  commits.
