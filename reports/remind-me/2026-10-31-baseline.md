- **346-r1 K2:** every run noticed chunked transfer encoding, but only under validation gaps
  or optional notes, never as a blocking finding (run 4 even probed it and saw the error). The
  judge credits the mention; the scorer counts only blocking findings, hence 0.00 against 5/5.
  This is the expert down-ranking a transport-compatibility issue, not missing it.
- **346-r2 K1:** a true miss. Runs checked truncation *before* the last chunk and confirmed it
  is refused; none checked a body that ends at `0\r\n` without the trailer's closing CRLF. The
  grader reproduced it at the head with a fake server (`Ok(...)` on `0\r\n` and on an
  unterminated trailer). Both 346 misses are in the hand-rolled HTTP/1.1 framing, which
  suggests a missing review axis (wire-format edge cases) rather than noise.
- **Over-grading:** 343-r1 K2 was graded P0 by runs 1–4 and P1 by run 5 against the key's P2
  (each applied "a stored secret is P0" while saying it was not a regression); 343-r2 run 2
  graded K1 P0; 346-r1 run 3 graded K1 P1. No under-grading.

## Real bugs beyond the keys

Confirmed by graders at each case head (probe crates and integration tests in exports under
`~/bench-work/grade/`, outside this repo) and re-checked on rusty-remind-me `main` at
`d79f67cd9`. All of the following are **still on main**. None filed (per instructions).

Redaction (PR 343):
- **`sk-` rule redacts ordinary slugs** (P1–P2; 343-r1 runs 1, 2, 3, 5): `sk-learn-compatible-…`
  and branch names with `sk-1234-…` become `[REDACTED:llm_api_key]`. Executed.
- **Quadratic scan on repeated anchors** (P1–P2; 343-r1 run 1, 343-r2 runs 2, 4): repeated `sk-`,
  `glpat-`, `-AIza` grow ~4× per doubling (`sk-` 200 KB: 3.7 s at head, 2.9 s on main). Executed.
- **Digits after a decimal point redacted as a card** (P1; 343-r1 run 2): `0.5555555555554444`
  → `0.[REDACTED:card_number]`. Executed (rate ~0.2% of random floats, not the report's 1.2%).
- **Space-separated number lists redacted as cards** (P2; 343-r1 run 5): `PRs 4012 4013 4015 4028`.
- **Diners `4-6-4` documented but never matched** (P2; 343-r2 runs 1, 2): `is_card` rejects a
  leading 3 except 34/37, so the `[4,6,4]` arm is dead and the doc comment is wrong. Executed.
- **Earliest-window card match leaves the card's tail visible** (P2; 343-r2 run 3):
  `4000 0000 0000 4111 1111 1111 1111` → `[REDACTED:card_number] 1111 1111 1111`. Executed.
- **A card stored as a JSON number survives the archive scrub** (P2; 343-r2 run 5):
  `boundary.rs` `redact_strings` scrubs strings only, while the dialog line redacts it, breaking
  ADR-0029's "neither returns a secret the capture redacted". Executed.

Consolidation evidence (PR 344):
- **Merge overwrites a client's own `metadata.evidence`** (P0 as graded; runs 2, 3). Executed.
- **Replacing metadata drops `evidence` but keeps the boost, so weight compounds** (runs 1, 3,
  4, 5). Executed (ratio 1.1434 vs f(3)=1.1099).
- **Evidence sum overflows** (runs 1, 3, 4): `u64::MAX` + 1 panics at `consolidation.rs:498`
  in debug. Executed.
- **Non-atomic merge double-counts on retry** (P1; all five runs): each write commits alone,
  no `Store::transaction`. Traced.
- **Concurrent merges on two nodes lose evidence** (P1; run 1): metadata is LWW per ADR-0004,
  so a counter in it is lossy. Traced.
- **A reverted decision counts as evidence** (P1; run 2), contrary to `promotions.rs:77`. Executed.
- Stale docs (`consolidation.rs:373`, `vitality.rs:111`) and missing partial-failure tests.

OpenAI embedder (PR 346):
- **Unset `REMIND_ME_OPENAI_EMBED_MODEL` wipes every stored vector on open** (P1; 346-r1 runs
  1, 2, 4; runs 3, 5 raised it only as a design question). Executed: 1 → 0 vectors.
- **Non-numeric / out-of-range embedding elements coerced to 0.0 / NaN** (P1–P2; 346-r1 runs 1,
  3, all five 346-r2 runs); a NaN score can panic the sort comparator at `vectors.rs:335`
  (56/2000 trials). Executed.
- **Release note says Ollama is unchanged, but the new `qwen3-embed` prefix changes Ollama
  Qwen3 queries** (P2; all ten 346 runs). Executed.
- **Status blames the daemon/ONNX when the openai model is unset** (P2). Executed.
- No tests for the openai resolver arm or the new fingerprint variables; `README.md:18` lists
  only Ollama and ONNX.

Fixed on main since the head (`fixed_since`, 3): missing tests for overlapping prefixes and
adjacent cards (343-r1 run 4), and a sync-path test for the evidence payload (344-r1 runs 4, 5).

## Grading

Graded blind against the clone at each case head by five grader agents, one per case, each
told to verify every non-key finding by execution or source trace rather than trust the report,
and to check `main` for `fixed_since`. Findings are items under a report's "Blocking findings";
design questions and optional notes are not graded.

- **Design questions (2):** 346-r1 run 3 and 346-r2 run 5 flag that the embedder identity omits
  the endpoint; the ADR-0002 #96 addendum fixes identity as backend, model and dimension.
- **Judgement calls:** mixed findings (e.g. bad index plus null coercion) matched to the key
  they contain; findings bundling a fixed part and an open part graded real; test-gap and stale
  doc findings graded real when still true on main; 344-r1's LWW counter and reverted-decision
  findings graded real (ADRs make LWW and reverted status intentional, not a lossy count).
- 344-r1 and 346-r2 graders note that P0 for the `evidence` overwrite is high; recorded as given.

## Blindness and network

- **Smoke test** with the suite's settings (run on `claude-haiku-5-5` to save usage, since the
  sandbox is enforced by the harness, not the model): Bash's `head -3 $EXPERT_AGENTS/README.md`
  failed with "No such file or directory" (sandbox denyRead); the file exists outside (2561 bytes).
- **Reachable domains:** `index.crates.io` and `static.crates.io` only. No run trace contains a
  request to any other host; runs that tried github.com were denied.
- **Cargo did not work for the workspace in any run.** The `rusty_mill` git dependency
  (`libs-2026.10.0`) is fetched from github.com, which the suite does not open, and `~/.cargo`
  is read-only in the sandbox, so nothing was cached to build offline. Formatting, as each
  run's own report states it (self-reported, not checked against the traces): 22 of 25 report
  workspace `cargo fmt --all -- --check` passing; 343-r1 runs 1 and 5 ran only standalone
  `rustfmt --check` on `redact.rs` and say workspace `cargo fmt` could not run; 343-r2 run 3
  ran standalone `rustfmt` and says its `cargo fmt` exit status was hidden by a pipe, so
  unconfirmed. Many copied single modules (`redact.rs`, `embedder.rs`) into
  scratch crates against the cached serde_json to run the PR's tests, clippy and probes. 344-r1
  runs executed nothing beyond fmt, so all their findings were source traces. A future run
  should open github.com read-only for cargo or pre-vendor the git dependency — but opening
  github.com lets Bash read the live reviews, so such a run would not be blind.
- **Each run** started from its own checkout of the case head fetched by SHA, with no later
  commits.

## Provenance limits

- **Extraction predates #12.** These runs were extracted with `bench extract` before PR #12
  (`b2a4d78`, take runs by the current suite's content keys) merged. A stopped single-job
  attempt ran first against the same suite, so the extraction was not verified to take only
  the 25 runs of the completed `--jobs 4` pass. Nothing shows contamination; a re-extraction
  with the fixed `bench extract` would settle it without new model runs. Not done here.
- **Shared scratch.** All runs' `$TMPDIR` was `~/bench-work/remind-me-tmp`, shared by the four
  concurrent runs (see Notes: 344-r1 run 3's `probe` and `cargo-home`). Independent probe
  isolation between runs is therefore not established; nothing shows one run read another's
  files.
- **Author-run.** The runs and grades were produced on the author's machine and have not been
  independently reproduced.
