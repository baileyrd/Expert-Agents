## Real bugs beyond the keys

Each was confirmed at the case head with synthetic data (executed probes unless marked
traced) and re-checked on MediBoard `main` at `6febbed`. **Not filed**, per the job brief.
Candidates, still on main:

- **P0, HTTP proxy (5-r1, all 5 runs).** The model client uses the default `urlopen`, so
  with `http_proxy` set the whole request, page text included, goes to the proxy instead
  of the model host. A CIDR `no_proxy` entry does not stop it. Fix: an opener with an
  empty `ProxyHandler`.
- **P1, model-written keys in `page_error.error` (6-r1 runs 1–4).** The ingest side of
  5-r1 K1: an unexpected key in a reply is stored verbatim in the error column.
- **P1, condition names in an exception (6-r1 runs 2–5).** An invalid `[conditions]`
  category raises an uncaught error whose message contains the condition name.
- **P1, claim evidence through an unreviewed finding (3-r1 runs 2, 5).** A confirmed med,
  lab or BP reading on a confirmed visit enters a claim's evidence and CSV when the only
  finding linking it to the category is still unreviewed. Graded real: `schema.sql` says
  claim views read confirmed or corrected rows only. Runs 3 and 4 raised it as a design
  question.
- **P1/P2, re-transcribed pages never re-extracted (5-r1, all 5 runs).** A page counts as
  done by pdf and page number alone, so changed text keeps the old extraction. This is
  PR 24's open "stale re-transcribed pages" finding, and it holds at the 5-r1 head.
- **P2, one out-of-range integer aborts the whole ingest (6-r1, all 5 runs).** For example,
  a BP value of 10^20 rolls back the run with 0 pages stored. Deep nesting raises
  RecursionError the same way.
- **P2, bad model replies crash the extract run (5-r1 runs 1, 2, 4, 5).** A lone surrogate,
  a 5000-digit integer, deep nesting or non-string content stops `run()`, and at temperature
  0 it stops on the same page every rerun.
- **P2, `SUMMARY:` inside a transcription truncates the model input (5-r1, all 5 runs).**
  `is_truncated` also misses such a page.
- **P2, provider key (6-r1 runs 1–4).** Drops surnames that are also titles (a visit loses
  its provider), merges different people, and strips non-ASCII letters.
- **P2, eval over-credits (5-r1 runs 1–4).** Edge-dot trimming makes ".5" equal "5"; units
  are case-folded; lab flag and dose are not scored.
- **P2, percent values stored as fractions under "%" (18-r1 runs 1, 2, 4).** A synthetic
  SpO₂ of 0.97 shows as "mean 0.97 %".
- **P2, a correction with an out-of-range number returns 500, not 422 (18-r1 runs 1, 3, 5).**
- **P2, export size limits (18-r1, all 5 runs), partly fixed.** `dc0be3c` added the zip
  cap. Children nested in one element are still all held in memory (about 200 MB for a
  synthetic workout with 400k children).
- **P2, smaller items:** negative `--limit` processes all pages but one (5-r1); a missing
  `paths.health_export` stops every command, not just the import (18-r1 run 4); orphaned
  conditions and providers after re-extraction (6-r1); colliding `[conditions]` keys
  silently resolve to the last (6-r1); two-digit years past today stored without the
  documented AMBIGUOUS flag (6-r1); `config.toml` read twice by ingest (6-r1, traced);
  U+2028 splitting a valid jsonl line (6-r1 run 4); a torn line cut mid-character breaking
  `eval` (5-r1 run 2); no test for `lab_result` in the review gate (6-r1, traced) or for the
  `+` CSV formula prefix (3-r1 run 4, by mutation).

Fixed on main since the head (`fixed_since`, 13): 18-r1's contract change without
recorded approval (approved as v3 in `3b9dc18`) and its stale README (`cae4b96`), and
6-r1's id reuse on re-ingest (AUTOINCREMENT in `2a23805`; an unchanged rerun still

## Grading

Graded blind against the clone at each case head by four grader agents, one per case. Each
was told to probe every non-key finding rather than trust the report, using synthetic data
and `tests/seed.py` only (probes kept outside this repo). Findings are the items under a
report's "Blocking findings". Design questions, optional improvements and pure coverage
notes that restate other findings are not graded.

- **Design questions (2):** 5-r1 run 1 F1 (P0) and run 4 F9 say page text goes over plain
  HTTP to the LAN model host, against README's "PHI never leaves the machine". That host is
  the base scaffold's committed default, and `contract/README.md` bars cloud APIs and
  network services beyond 127.0.0.1, not a configured LAN model host. The README line and
  the config disagree, which Nano may want to settle.
- **Judgement calls:** 18-r1's contract-approval findings counted `fixed_since` (v3 approved
  on main; strictly a v2 approval was never recorded). 6-r1 two-digit years counted real
  (the pivot is documented, but the documented AMBIGUOUS flag is never set). 3-r1's
  unreviewed-finding link counted real (it would be a design question if the code
  docstrings count as documentation; precision stays 1.00 either way).
- **PR 20 / PR 24:** PR 20's later findings did not come up as 18-r1 findings. Of PR 24's,
  only "stale re-transcribed pages" came up (5-r1), and it holds at that head.

## Blindness and network

- **Smoke test** with the suite's settings rendered into a scratch `.claude/settings.json`:
  `cat $EXPERT_AGENTS/README.md` returned "No such file or directory" (sandbox denyRead).
  `ls $TARGET` and `ls ~/.claude` were empty the same way. `curl https://github.com` was
  refused (`deny network-outbound github.com:443`). `pypi.org` answered 200, and
  `files.pythonhosted.org` answered 404 at its root, so it was reachable.
- **Reachable domains:** `pypi.org` and `files.pythonhosted.org` only. Two runs (18-r1 run 4,
  6-r1 run 2) asked Bash to open `github.com`, `*.githubusercontent.com` and
  `python-build-standalone.astral.sh` to download Python 3.13 with `uv`. Both fell back to
  the system 3.14, and 18-r1 run 4's report says the hosts were denied. Eval-Kit's traces
  keep tool calls, not results, so that rests on the runs' own output. No tool call in any
  trace fetches the review or the GitHub API.

  failed 19 of 20 runs and every judge call on an expired OAuth session. After re-login
  the CLI had updated to `2.1.316`, which changed every run key, so all 20 runs here come
  from the second attempt. The one stale 2.1.314 record in the store is not used.
